# 已有模型更新工作流

## 进入前
找到用户指向的最新模型与文件身份，核对公司、版本、单位、工作表、历史/预测分界、命名区域和外链。先保留可恢复版本；不覆盖不相干工作簿或默认重建模型。无模型时完成资料收集与更新清单后请求提供工作簿。

## 更新过程
1. 列更新表：科目、来源、原值、新值、单位、期间、单元格/命名区域、实际或假设、理由。
2. 季报累计转单季、币种、合并范围、重述遵从共享会计约定。历史actual只替换对应输入，保留计算公式；财报重述另标版本。
3. 未来预测保持原假设，除非用户已授权更新预测且新证据足以支持。授权更新时按经营驱动调整，列假设前后及影响；没有必要反复征求机械确认。
4. 保留sheet名称/位置、公式、样式、外链及命名区域；遇不支持特性明确具体影响并选择能保留的工具，不静默丢失宏/公式。
5. 重算后核对资产负债平衡、三表现金滚动、年度/季度衔接、公式错误、实际替换覆盖、预测联动与估值桥接。检查旧/新财务与估值变化是否由修订解释；未重算就明确状态。

## 交付
原格式更新文件（按文件身份/版本规则保存）、修订日志、前后变化表、失败/未测试项及待确认假设。用handoff传递给earnings或DCF的事实版本，避免多个模块分别修改同一模型。
