# 主报告执行与专项协作

主报告是初步了解公司的默认交付，先完成可复核的六项财务诊断，再提出少量深入问题。必查指标见main-report-contract.md，公式见metric-definitions.md，避免在本文件重复维护。

## 1. 界定研究对象
核实公司、证券代码、合并主体、截止日及实际已披露的完整财年；默认5年。更长报告可保留全部历史，但扣非ROE最终评估默认使用最近5个完整财年。额外取得首年期初余额。
依据收入来源选择2C商品、2B、混合、服务或金融模式，说明行业周转分支。同行先按产品/模式筛选3–5家；不同业务可用不同同行，不为凑数纳入不可比公司。

## 2. 先登记数据状态，再形成结论
每项数据分别登记已核实、部分缺失、未披露/不足、不适用。缺失不是零，不是正常，也不是异常。存在已有数值但历史不足时标部分缺失，并保留可得年份。
ROE分为普通、法定扣非、分析调整、Non-GAAP四种；自算平均权益与披露加权口径分开。没有可核实扣非数据就明确保留缺口，不替换指标或编分数。亏损分母对应现金含量N/M，与原始利润/CFO金额并列。

## 3. 计算并核对
复用领域脚本计算和三表勾稽，通用能力执行取数、绘图与表格。主报告选取的FY必须真实完整、连续或有明确历史断点说明。现有数值、缺失原因、异常判断使用不同字段，不把覆盖率当经营质量。
判定异常前先排除单位、币种、期间、会计口径、重述和平均余额错误。无法修正的失败检查影响相关结论；不把无关公司的失败当目标公司稳定性证据。

## 4. 按七步回答问题
依据主报告契约完成趋势与同行图，正常项1–2句；异常项识别最主要一级驱动、至少两表验证、可能业务原因和所需证据。对初步结论没有影响的支线不无限展开。
仅在主报告需要额外证据时内部调用专项Skill：comps负责同行可比数据；earnings负责最新季度补充。按[模块调用契约](../../../shared/module-invocation.md)明确support角色，输出嵌回现有章节；不自动生成另一份完整专项报告，不重复取数。

## 5. 汇总三个评估维度
分数、质量、稳定性各用自身依赖的数据。同行扣非缺失可能使分数不可得，但同口径公司历史足够时仍可判断稳定性；已有经营和现金证据仍可说明赚钱机制，并标清适用口径。
分数定义和统计方法只维护于roe-assessment.md。高相对分不能掩盖绝对亏损；数学贡献不能代替经营因果。

## 6. 完成报告后衔接研究
按report-template.md生成摘要、正文、评估、验证问题和数据附录，并执行quality-gates.md。必查缺口必须让读者看见，不能只藏在JSON或脚本日志。
独立季度点评、独立对比、DCF和模型更新按照用户任务直接进入专项；不强制先完整跑主报告。用户明确连续任务时保留全部交付及顺序；未明确顺序且任务冲突时先做不依赖澄清的准备，再确认实质歧义。
显式深挖某指标仍由核心deep模式复用指标树，作为独立后续任务；没有必要为了深挖另加重复Skill。
