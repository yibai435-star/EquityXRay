# 异常识别与研究优先级

按公司自身历史→同行→行业特征→商业模式→指标逻辑关系判断，结合变化额、占比、持续时间与业务影响。不套全行业固定阈值，不做主观分数或红黄绿评级。

分类仅为“正常 / 值得关注 / 需重点拆解”；“数据不足”和“不适用”是覆盖状态，不是风险等级。未查不能写正常。

| 扫描范围 | 核对关系 |
|---|---|
| 增长质量 | 收入增速vs应收（含适用票据/合同资产）；收入及成本增速vs存货；经营叙事与财务变化 |
| 回报与盈利 | ROE及三因子、毛利率、净利率、各费用率、总资产周转历史与可比差距 |
| 利润质量 | 合并净利vsCFO；归母vs扣非归母；信用减值、资产减值、投资/公允价值/其他收益、营业外收支 |
| 资产与偿债 | 有息债务vs可动用现金、商誉/净资产、预付款、在建工程、现金CapEx、债务期限及利息负担 |
| 经营与治理附注 | 关联交易/资金占用、大客户依赖、担保/质押/诉讼、大额资产处置、研发资本化、合同负债、审计意见/持续经营 |
| 可比性 | 会计政策/估计变更、并购/剥离、重分类、重述和期初期末衔接；先处理数据问题再判断经营异常 |

例：收入+50%、存货+30%与收入+5%、存货+60%经济含义不同；后者也需结合订单、备货、并表、行业周期验证，不能直接认定积压。

正常项给图与1–2句解释；异常项按财务影响、持续性、跨表背离和证据缺口确定篇幅，不平均分配。缺乏充分证据时不凑异常数量。

每个异常必须交代：
1. 为什么异常：相对基准与量化影响。
2. 可能原因：至少主假说与可检验替代解释，按证据强弱排序。
3. 进一步验证什么：具体字段/资料、验证方法及可能改变的判断。

使用[指标树](metric-tree.md)继续下钻，以[跨表验证](cross-statement-validation.md)排除数据矛盾，以[业务解释](business-interpretation.md)形成机制。完整覆盖表留在附录，正文只重点写有意义的异常。
使用“该项目存在值得进一步核实的异常信号”，禁止直接将异常等同于造假。
